# dsh-write-protect v0.1.0

Date: 2026-09-08

首个发布版本. 为 DSH 沙箱补上工作区子路径级别的只读保护: 声明过的路径 (默认任意层级的 `.git`) 对模型可见的全部写入口保持只读, 沙箱内的 CLI 命令和 write/edit 工具都会被拒绝写入, 读取不受影响. 安装前请先阅读 Upgrade Notes.

## Highlights

- 为 DSH 沙箱补齐工作区子路径只读保护, 默认保护任意层级的 `.git` 目录, 防止模型改动版本历史.
- 进程沙箱与 write/edit 工具双入口同时拦截: Linux 用 bwrap 叠加 ro-bind, macOS 用 Seatbelt 追加 deny 规则, 读取不受影响.
- Web Settings 新增 gitignore 风格的 "写入保护" 配置页, 保存后实时生效并持久化, 覆盖 patch 部署的 base 配置.
- 保护路径支持 `*`, `**`, `?` 通配与 `!` 取反, 相对条目按当前会话的工作区根解析.

## Features

- 沙箱 provider: 在官方 `workspace-write` 沙箱之上叠加保护路径的只读约束, Linux (bwrap) 与 macOS (Seatbelt) 均覆盖.
- fs 围栏: write/edit 工具在官方模式围栏之前追加保护路径检查, `danger-full-access` 下该拒绝仍然生效.
- systemPrompt: 告知模型哪些路径受保护, 减少反复尝试写入.
- 配置入口: patch 的 `readOnlyPaths` 数组与设置页 patterns 文本经同一解析器展开, 三个执法半区消费同一份结果; 置为空列表即整体停用.

## Known Limitations

- Linux 上 bwrap 不可用时的 Landlock 回退是纯 allow-list 并集, 无法表达子路径例外, 命令按官方 profile 运行并记录一次告警; Windows 不挂载 provider 半区, 由 fs 围栏覆盖 write/edit 工具.
- 保护路径在宿主上尚不存在时 (例如还未 `git init`), 该路径的 ro-bind 会跳过并告警, fs 围栏的拒绝不受影响.
- `danger-full-access` 下 bash 的写入不经进程沙箱, 不受本插件保护.

## Upgrade Notes

1. 执行 `dsh plugin --profile web add azazo1/dsh-write-protect` 安装, 固定版本使用 `#v0.1.0` 后缀.
2. 安装后 patch 会替换 base bundle 的 `sandbox-policy`, `fs-sandbox` 与 `sandbox` 三行, 无需重启 `dsh web`.
3. 验证方式: 在受保护的工作区让模型对 `.git` 内文件执行写入, 应被沙箱或 write/edit 工具拒绝.
