# dsh-write-protect v0.1.0

Date: 2026-09-08

首个发布版本. 为 DSH 沙箱补上工作区子路径级别的只读保护, 并支持在 `workspace-write` 下声明工作区外的额外可写根. 安装前请先阅读 Upgrade Notes.

## Highlights

- 为 DSH 沙箱补齐工作区子路径只读保护, 默认保护任意层级的 `.git`, 防止模型改动版本历史.
- write / edit 工具在全平台挡住保护路径; Linux / macOS 上 bash 等命令同样生效, 并在 `workspace-write` 下把额外可写根并进 allow-list.
- Web Settings 新增 gitignore 风格的 "写入保护" 页, 保存后实时生效; 预览按当前会话 cwd 展开, 不必先保存.
- 额外可写根支持 `~`, `$NAME` / `${NAME}` 与相对 `..` 路径, 不打穿 `read-only`.

## Features

- 沙箱 provider: Linux bwrap 叠加 ro-bind / `--rw`, macOS Seatbelt 追加 deny 与额外可写.
- fs 围栏: write / edit 在官方模式围栏之前检查保护路径与额外根, `danger-full-access` 下保护路径仍然拒绝.
- 保护路径: gitignore 语义, `//` 表示文件系统绝对路径, 通配与 `!` 取反按 last-match-wins 解释.
- 设置页预览: 把当前草稿交给 Host 展开, 列出生效路径与被忽略或拒绝的行.
- systemPrompt: 告知模型哪些路径只读, 哪些额外根可写.

## Known Limitations

- Windows 上 bash / pwsh 既挡不住保护路径, 也拿不到额外可写根; write / edit 两者都生效.
- Linux 落到 Landlock 时无法单独保护子路径, 命令按官方沙箱跑并告警一次; 额外可写根可以加 `--rw`.
- `danger-full-access` 下 bash 不进沙箱; write / edit 仍然挡保护路径.
- 通配只覆盖展开当时已存在的路径; 字面条目即使尚不存在, write / edit 也会拒绝.
- 单次遍历最多 5000 个节点, 结果缓存 5 秒.

## Upgrade Notes

1. 执行 `dsh plugin --profile web add azazo1/dsh-write-protect` 安装, 固定版本使用 `#v0.1.0`.
2. 预构建包见 GitHub Release 的 `dsh-write-protect.tgz`, 安装时跳过 `allowBuilds`.
3. 安装后 patch 会替换 base bundle 的 `sandbox-policy`, `fs-sandbox` 与 Linux / macOS 上的 `sandbox` 行, 无需重启 `dsh web`.
4. 验证方式: 在受保护工作区让模型写入 `.git` 内文件, 应被拒绝; 额外可写根默认为空.
