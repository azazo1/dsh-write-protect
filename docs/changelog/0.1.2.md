# dsh-write-protect v0.1.2

Date: 2026-09-17

这一版修掉两个"装上插件整个 DSH 就不可用"的问题:

1. DSH `0.1.6` 上官方 `SandboxProvider.confine()` 改成异步后, 插件仍按同步契约覆写, 每条走沙箱的命令都在 `confine()` 里抛 `TypeError`, 沙箱整个挂掉;
2. 保护路径展开在 `resolve()` 里做无上限的同步 glob 遍历, 工作区一大 (例如把家目录当工作区) 就把 Host 事件循环占死几十秒到几分钟 —— 表现是**整个 `dsh web` 卡住**, 连首页都打不开.

依赖版本线同步抬到 `0.1.6-alpha.1`, 并补上 Linux bwrap 的内核级端到端测试.

## Highlights

- 修复: DSH `0.1.6` 上载入插件后所有被沙箱约束的命令 (bash 等) 直接失败, 沙箱看起来"挂掉".
- 修复: 装插件后整个 `dsh web` 卡死. 同步展开新增队列项预算 (500) 与墙钟上限 (50ms), 被截断的深层匹配由后台分片遍历补齐; 实测 `resolve()` 在工作区 = `/home/vagrant` 时从 **超过 45s 不返回** 降到 **70ms 左右**, 首页并发探测保持几十毫秒.
- provider 半区的 `confine()` 改为 `async` 并 `await` 官方结果, 同时把官方的 `signal` 参数透传下去.
- 依赖: `peerDependencies` / `devDependencies` 的 `@deepseek-ai/*` 从 `^0.1.2-rc.1` 抬到 `^0.1.6-alpha.1` (cordis `^4.0.2`), 锁文件同步.
- 测试: 新增 `test/bwrap.e2e.spec.ts`, 在 Linux 上用真实 bwrap 断言保护路径写入被内核拒绝 (EROFS)、读取照常、额外可写根可写; 新增有界展开与后台补全的用例.
- 重构: 纯 gitignore 匹配抽成独立模块 `src/gitignore.ts` (零运行时依赖), **write / edit 围栏改为直接按模式逐路径判定**, 不再依赖枚举出来的路径清单 —— 深层嵌套、尚未存在、枚举预算之外的匹配一样挡得住, 且每条写入只做几次正则. 实测: 工作区 = `/home/vagrant/workspace` 时枚举清单被截断到 1 条, 而不在清单里的深层 `.git` 依然被拒 (`FS_SANDBOX_DENIED ... matches ".git"`).

## Bug Fixes

- 官方 `@deepseek-ai/dsh-sandbox` 自 `0.1.6-alpha.1` 起把 `SandboxProvider.confine()` 从 `ConfinedArgv` 改成 `Promise<ConfinedArgv>`, 并新增 `signal` 参数 (`0.1.5-rc.1` 仍是同步签名). 本插件原来的覆写是同步的, `super.confine()` 返回的 Promise 上读 `.argv` 直接抛 `TypeError: Cannot read properties of undefined (reading '0')`; `dsh-bash-sandbox` / `dsh-terminal-bash` / `dsh-pwsh-sandbox` / `dsh-ptc-runtime-node` / `dsh-api-terminal-controller` 全部 `await ctx.sandbox.confine(...)`, 因此每条命令都失败, 表现为沙箱整体不可用. 现在覆写为 `async`, `await` 官方结果后再叠加保护路径、额外可写根与 broker 加固.
- 取消语义随之恢复: 官方在 `confine()` 入口 `throwIfAborted()`, 覆写现在把 `signal` 原样转发, 中止的调用会照常拒绝, 不再被同步覆写吞掉.
- **整个 `dsh web` 卡死**: `policy.resolve()` 是同步契约, 而默认保护条目 `.git` 是非锚定通配, 展开时必须遍历整个工作区才能找到任意层级的匹配. v0.1.1 为了"不漏掉深层的 `.git`"去掉了节点上限, 于是工作区一大家目录级 (本机有 80 个会话的 cwd 就是 `/home/vagrant`) 就出事: 一次 `resolve()` 同步遍历几十秒到几分钟, 期间 Host 事件循环完全被占死. 而 `resolve()` 在 systemPrompt 组装、bash / 终端 spawn、fs 写围栏、设置页预览上都会走到 —— 一次调用就冻住整个 web. 现在:
  - 同步展开有 **队列项预算 (500) + 墙钟上限 (50ms)** 双重上限, 任一先到即停止遍历, 已找到的路径立即生效 (广度优先, 浅层优先, 工作区根上的 `.git` 通常头两项就命中), 并告警说明结果不完整;
  - 被截断的根交给后台异步展开按 **20 000 项 / 10s / 15ms 时间片** 分片补齐, 每片之间让出事件循环, 再大的工作区也不会阻塞 Host;
  - 补齐结果与已有结果取**并集**合并, 更差的同步部分结果不会把已发现的深层匹配置换掉; 补全也到顶 (家目录级) 时记为该根已放弃, 不再反复做无望的全量扫描, 告警里给出"改用锚定条目 (如 `/.git`)"的建议;
  - 设置页预览改走异步完整展开, 不再用同步短预算静默截断结果.
- 展开语义 (gitignore 模式、取反、符号链接剪枝、`//` 绝对路径) 一行未改, 变更只在"一次展开能看到多少候选"以及何时补齐.

## Refactor

- 新增 `src/gitignore.ts`: gitignore(5) 语义的解析、编译与逐路径匹配, 纯字符串/正则, 不碰文件系统, 不依赖任何 `@deepseek-ai/*` 包. 对外是 `compileGitignore(text).match(path, workspaceRoot, isDir)`, 返回命中的条目与围栏起点. 它同时是枚举展开的语义来源, 两侧不会漂移.
- `src/patterns.ts` 只保留**枚举**: 有界同步遍历、后台分片补全、额外可写字面路径. 它不再承担匹配判定, 也不再导出解析函数.
- `src/fs.ts` 的 write / edit 围栏改为 `PatternSet.match(targetKey, workspaceRoot, false)`: 命中可以是目标自身, 也可以是它的某个祖先目录 —— 这就是"被保护的目录连同其后代一起挡"的前缀围栏语义. 拒绝信息现在会指出命中的模式与围栏起点. 执行 policy 上没有模式文本时 (不是本插件的 policy service 生成的) 退回原来的枚举路径前缀比较.
- `policy.resolve()` 在执行 policy 上同时注入 `readOnlyPatterns` (原文, 给 fs 围栏) 与 `readOnlyPaths` (枚举, 给进程沙箱). 提示词在枚举被截断时明确区分两侧: 工具侧按模式全覆盖, 命令侧只钉住已枚举到的浅层路径, 并建议改用锚定条目.
- 行为边界两处收紧, 都是为了与 gitignore 一致: 相对条目不作用于工作区**外**的同名路径 (以前非锚定条目会按绝对路径分段误命中); 尾部 `/` 的条目对文件目标不再命中 (write / edit 的目标是文件, 只匹配目录的条目只会在祖先目录上生效).
- 测试: 新增 `test/gitignore.spec.ts` (12 个纯逻辑用例, 不需要任何临时目录), `test/fs.spec.ts` 增加"启动后才出现的深层路径仍被拒"、"尾部 `/` 与同名文件"、"非锚定条目不越过工作区边界"与原文注入的用例.

## Known Limitations

- 引擎版本线是硬边界: 本版只支持 `0.1.6-alpha.1` 及同线的 `@deepseek-ai/*`. 仍在 `0.1.5` 及更早引擎上的部署请继续用 v0.1.1 —— 那条线上官方 `confine()` 是同步的, 本版的异步覆写同样不兼容.
- 非锚定通配条目 (默认的 `.git`) 在超大工作区上, **命令侧**只能保护"有界同步 + 有界后台"两次遍历覆盖到的匹配: 家目录级工作区仍可能有更深层、更靠后的 `.git` 没被钉进沙箱 profile. write / edit 侧不受此限 (按模式全覆盖). 要让命令侧也无条件覆盖, 请改用锚定条目 (如 `/.git`), 或按仓库分别声明路径. 命中该情况时 Host 日志里会出现展开不完整的告警, 提示词里也会说明两侧差异.
- 其余限制同 v0.1.1 (Windows 上 bash / pwsh 挡不住保护路径; Linux 落到 Landlock 时无法表达子路径保护; `danger-full-access` 下 bash 不进沙箱).

## Upgrade Notes

1. 升级前先确认引擎版本: `dsh --version` 应为 `0.1.6-alpha.1` 或同线版本.
2. 固定版本安装 `dsh plugin --profile web add azazo1/dsh-write-protect#v0.1.2`; 跟随最新版则去掉 `#v0.1.2`.
3. 升级后 `dsh plugin --profile web add ...` 会重装依赖; 配置 (`readOnlyPaths` / `writablePaths` / `hardenBroker`) 与设置页内容不变, 无需重启 `dsh web`.
4. 验证方式: 载入插件后在受保护工作区执行一条命令 (例如 `git status` 或任意 `echo`), 应当正常返回; 再让命令写 `.git` 内文件, 应得到 `Read-only file system`. 若此前 `dsh web` 一装上插件就卡住, 升级后应先能看到首页加载、设置页可以正常打开; 家目录级工作区会在 Host 日志里看到"展开不完整"的告警 (属预期).
