# dsh-write-protect v0.1.1

Date: 2026-09-12

这一版堵上两处能绕过只读保护的漏洞, 并修掉 Windows 上额外可写根的解析错误. macOS 用户升级后 broker 逃逸加固默认开启, 如果确实需要从沙箱内驱动宿主 GUI, 请先读 Upgrade Notes.

## Highlights

- macOS: 堵住 `open` 经 launchd 把命令挪到沙箱外执行的逃逸, `deny file-write*` 不再被整条绕开, `read-only` 下同样生效.
- Windows: 额外可写根里的 `\` 不再被当作转义符, `C:\Users\me\caches` 这类路径不会退化成落点不确定的盘符相对路径.
- glob 展开去掉 5000 节点预算, 改为按目录剪枝, 并停止跟随目录符号链接, 超大工作区不再漏掉深层路径.
- 设置页新增 "macOS broker 逃逸加固" 开关, 需要从沙箱内驱动宿主 GUI 时可以关掉.

## Features

- 设置页: 新增 macOS broker 逃逸加固开关, 对应 patch 的 `hardenBroker`, 缺省开启; 关掉后 provider 原样返回官方 argv.
- 保护路径与额外可写根: 补上 Windows 写法说明, 保护路径的绝对条目写作 `//C:/Users/me/secret`, 额外可写根按字面反斜杠解析.
- 市场展示: 仓库内声明截图并内嵌到 README 的设置页一节.

## Bug Fixes

- macOS: 官方 profile 的 `(allow default)` 让沙箱内一条 `open x.app` 经 launchd 派生出不继承 profile 的进程, 从而在沙箱外任意写入; 现在在 profile 末尾追加 `(deny mach-lookup (global-name-prefix "com.apple.coreservices"))`, `(deny appleevent-send)` 与 `(deny mach-priv-task-port)`. SBPL 按 last-match-wins 解释, 追加在末尾才能盖过 allow; 名称过滤器按 reverse-DNS 分段匹配, 收窄到子服务无效, 只能整段拒绝.
- macOS: 加固不再只认 `workspace-write`, 因为 `read-only` 的官方 profile 形状相同, 同样是 `(allow default)`.
- Windows: 额外可写根解析改为平台感知, `\` 只在 POSIX 上转义, Windows 上按分隔符原样保留; `~\caches` 与 `~/caches` 一样展开为家目录, 展开, 盘符判定与工作区包含比较统一走 win32 路径 API.
- Windows: 盘符相对路径 (`C:caches`) 改为拒绝并告警, 它的落点取决于进程当前目录, 会静默给出调用方从未指定的可写根.
- Windows: 保护路径的 glob 元字符检测不再跳过 `\` 后面的字符.
- glob 展开: 目录性检查改用 `lstat`, 指向目录的符号链接不再走进去, 避免 `Applications -> /Applications` 这类链接把大项目启动扫卡住.

## Performance

- glob 展开: 删除 `EXPAND_NODE_BUDGET`, 超大工作区不再因节点预算截断而漏掉深层路径; 已经会被保护的目录不再往里扫, 被 `!` 放行的目录仍继续展开.

## Known Limitations

- Windows 上 bash / pwsh 既挡不住保护路径, 也拿不到额外可写根; write / edit 两者都生效.
- Linux 落到 Landlock 时无法单独保护子路径, 命令按官方沙箱跑并告警一次; 额外可写根可以加 `--rw`.
- `danger-full-access` 下 bash 不进沙箱; write / edit 仍然挡保护路径.
- 通配只覆盖展开当时已存在的路径; 字面条目即使尚不存在, write / edit 也会拒绝.
- 展开结果缓存 5 秒, 逐次 tool call 复用.
- broker 加固是纵深加固: 它关掉的是 launchd / LaunchServices 这条代理通道, 沙箱内的进程仍可通过其他本地守护进程 (Docker socket, ssh-agent 一类) 让沙箱外的服务代劳.

## Upgrade Notes

1. 固定版本安装 `dsh plugin --profile web add azazo1/dsh-write-protect#v0.1.1`; 跟随最新版则去掉 `#v0.1.1`.
2. macOS 上 broker 加固默认开启, 常规命令 (node, git, pnpm, python, curl, tar, rsync) 不受影响. 若流程确实需要从沙箱内 `open` 宿主 app, 在设置页关掉 "macOS broker 逃逸加固", 或在 patch 的 policy 行给出 `hardenBroker: false`; 关掉即恢复可以被 `open` 打穿的状态.
3. Windows 用户检查额外可写根里的反斜杠路径: 它们现在按字面解析, 之前被吃掉分隔符而写成 `C:Usermecaches` 的行需要改回 `C:\Users\me\caches`. 盘符相对路径会被拒绝, 并出现在设置页预览的 "未生效" 列表里.
4. 验证方式: 保护路径与额外可写根的行为不变, 用设置页的预览按钮确认生效路径; macOS 上可以让命令执行 `open` 一个宿主 app, 应当被拒绝.
